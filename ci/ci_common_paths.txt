# Common code paths whose changes force-run *all* per-board build-*.yml workflows.
#
# Edit this list (and ci/board_families.json), then re-run
#   uv run python ci/render_workflows.py
# to regenerate the `on: paths:` blocks of every per-board workflow. The CI
# drift gate (.github/workflows/ci-workflow-drift.yml) enforces this.
#
# Scope: these paths force-run the CORE boards only -- the entries marked
# `"core": true` in ci/board_families.json. That is three boards, one per
# toolchain family that shared code can plausibly break:
#
#   uno       AVR      (avr-gcc)
#   esp32dev  ESP32    (Xtensa)
#   teensy41  Teensy   (ARM)
#
# All three run on ubuntu-latest and share one soldr build cache
# (`cache-key-suffix: fbuild-rust-debug` in template_build.yml is
# board-independent), so the Rust rebuild happens once and the other two
# hit it.
#
# This changed in FastLED/fbuild#1396. Being broad here used to mean a
# one-line edit in fbuild-core scheduled all 80 board builds, ~94 checks per
# PR; with a strict up-to-date merge rule, every merge then invalidated every
# other open PR and the queue serialized behind full board sweeps. The safety
# net is the nightly sweep (.github/workflows/nightly-platforms.yml), which
# still runs every board at 3am.
#
# So being broad here is cheap: it costs 3 workflows, not 80. Add a path when
# a change to it could plausibly break a build on any family.
# Family-specific code stays in board_families.json crate_paths and triggers
# its whole family directly -- an ESP32 change still runs all 9 ESP32 boards.
